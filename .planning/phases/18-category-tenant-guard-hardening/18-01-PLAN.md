# Plan 18-01 - Harden Category Mutate Tenant Authorization

## Objective
Close the category authorization lifecycle gap by ensuring shop-level category mutations validate active tenant membership consistently with other tenant APIs.

## Non-Goals
- No frontend UI changes.
- No Prisma schema/migration changes unless tests reveal a missing constraint.
- No rewrite of public category read behavior.

## Implementation Plan

### Step 1 - Confirm route authorization matrix
- Review current `CategoriesController` guard/decorator combinations.
- Document intended behavior:
  - Anonymous/optional auth can read category lists/details.
  - Platform super can mutate global categories without tenant context.
  - Shop admin can mutate only active-shop scoped categories.
  - Shop staff remains read-only for mutating methods via `RolesGuard`.

### Step 2 - Patch guard wiring safely
- Add active-shop validation to the shop-level category mutate path without changing platform-super global behavior.
- Do **not** naively add `TenantGuard` to mixed platform+tenant routes if that would require platform_super users to have an active shop.
- Choose one safe implementation path before coding:
  1. Split platform-only global category routes from tenant-scoped category routes, then apply `TenantGuard` only to tenant-scoped routes; or
  2. Enhance `RolesGuard` tenant-role lookup to include `shop.is_active` for tenant-role checks while keeping platform-role checks tenant-independent.
- Keep service-level `assertCanMutateCategory` as defense-in-depth.

### Step 3 - Add regression coverage
- Add tests that simulate an inactive active shop and assert shop user cannot mutate a shop category.
- Add tests that platform_super behavior remains valid for global category mutation.
- Add tests/read assertions confirming public category read endpoints are unchanged if controller-level tests exist.

### Step 4 - Verify
- Run targeted category/guard tests first.
- Run backend lint and full backend Jest suite.
- Run backend build if implementation touches module/DI wiring.

## Acceptance Criteria
- Inactive active shop cannot mutate category using stale JWT context.
- Shop category mutation still works for active shop admin.
- Shop staff still cannot perform mutating category methods unless explicitly allowed.
- Platform super can still manage global categories.
- Tests cover the inactive-shop regression.

- `pnpm --filter ./backend build`

## Risks / Notes
- The current category mutate routes are mixed platform+tenant. Adding `TenantGuard` naively can deny platform_super users without an active shop; validate route behavior before coding.
- `RolesGuard` currently caches shop roles for 30 seconds; if moving `shop.is_active` checks into `RolesGuard`, cache shape/invalidation must avoid stale inactive-shop authorization.
