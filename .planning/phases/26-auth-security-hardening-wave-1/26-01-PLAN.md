**Phase:** 26 — Auth Security Hardening Wave 1
**Plan:** 26-01
**Issue:** #232
**Status:** Not started

---

## Goal

Ghi log mọi sự kiện đăng nhập (success/failed) ra stdout JSON; sinh `trace_id` UUIDv7; gắn `X-Trace-Id` response header; optional persist vào `login_audit_log` PostgreSQL.

---

## Implementation Steps

### Backend

1. **Tạo `audit/login-audit.service.ts`**
   - `logLoginAttempt(payload: LoginAuditPayload)` — fire-and-forget, không throw
   - `payload`: `{ trace_id, user_id, email, shop_id, ip_address, user_agent, status, failure_reason }`
   - Phase 1: `console.log(JSON.stringify(payload))` với format chuẩn
   - Phase 2 (optional trong cùng plan): persist vào `login_audit_log` table

2. **Migration: bảng `login_audit_log`**
   ```sql
   CREATE TABLE login_audit_log (
     id BIGSERIAL PRIMARY KEY,
     trace_id UUID NOT NULL UNIQUE,   -- UUIDv7
     user_id INT,
     email VARCHAR(255) NOT NULL,
     shop_id INT,
     ip_address INET,
     user_agent TEXT,
     status VARCHAR(20) NOT NULL,     -- 'success' | 'failed'
     failure_reason VARCHAR(50)
   );
   CREATE INDEX ON login_audit_log (user_id, trace_id DESC);
   CREATE INDEX ON login_audit_log (shop_id, trace_id DESC);
   CREATE INDEX ON login_audit_log (status, trace_id DESC);
   ```

3. **`auth/auth.service.ts` — sinh trace_id trước mọi logic**
   - `import { v7 as uuidv7 } from 'uuid'` (đã có trong deps)
   - Sinh `trace_id = uuidv7()` đầu hàm `login()`
   - Gọi `loginAuditService.logLoginAttempt(...)` sau khi biết `status`

4. **`auth/auth.controller.ts` — gắn X-Trace-Id header**
   - `@Res({ passthrough: true })` + `res.setHeader('X-Trace-Id', trace_id)`
   - Hoặc dùng `@Header('X-Trace-Id', ...)` nếu không cần passthrough

5. **Invariants**
   - Log cả failed login (quan trọng nhất về bảo mật)
   - Không log password/token
   - Logging không làm chậm login > 10ms
